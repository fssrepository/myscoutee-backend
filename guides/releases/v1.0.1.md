# MyScoutee 1.0.1

Integration API release, 2026-09-19. Version `1.0.1`, tag `v1.0.1`.

## Included

- A deliberately small, authenticated integration API for creating asset and
  event batches with at most 1000 items per request.
- Caller-owned UUIDs in `id` and stable MyScoutee resource UUIDs returned in
  `externalId`, including idempotent retry results.
- Optional asset and event images uploaded as bytes in the same multipart POST;
  the server retains the original and creates 128 px, 640 px and 1280 px WebP
  variants.
- Up to three expiring integration keys per user. The first external client UUID
  claims its key; missing, invalid, expired, revoked or differently claimed keys
  are rejected.
- Profile API settings using the existing popup, form, loading and confirmation
  patterns, plus Operator-configurable and cached public API Base URL.
- Java 17 reference SDK/CLI, OpenAPI 3.1 description, versioned test payloads and
  the Integration API Guide PDF.
- Reliable ordered MongoDB i18n seed synchronization so translated labels become
  visible only after their complete message set has been imported.

## Verified

- Frontend and backend dev watchers completed successfully and the running dev
  stack remained healthy behind Nginx.
- Real Java CLI requests through Nginx created assets and an event, returned the
  caller `id` with its MyScoutee `externalId`, and returned `existing` with the
  same mapping on retry.
- A multipart event image produced the original plus all three configured WebP
  sizes in object storage.
- Missing and invalid keys returned HTTP 401. Missing client configuration and
  malformed JSON failed locally; invalid UUIDs and required fields returned
  per-item `rejected` results with machine-readable error codes.
- All seven Java client tests passed. The generated nine-page API PDF was checked
  for metadata, A4 layout and the previously problematic table wrapping.

## API compatibility

The API root is supplied by Operator configuration and ends in
`/api/integrations/v1`. The public operations are `POST /connect`,
`POST /assets` and `POST /events`. This is a write-oriented integration surface,
not a general profile, booking or resource query API. Images are optional parts
of the asset or event POST; there is no separate image endpoint or remote-image
download behavior.

The Debian package is built separately and uploaded by the release owner. Other
release metadata and client artifacts are published with the GitHub release.
