# MyScoutee 1.0.0

Same-version amd64 release replacement, 2026-09-18. Version `1.0.0` and tag
`v1.0.0` are retained. Frontend build: `stable-20260918-operator-layout`.

## Included

- Compact Operator configuration save actions and Firebase/HTTPS test buttons.
- A separate Debian 13 minimal host-preparation helper in client tools.
- Reliable first MongoDB startup and seed-import completion during installation.
- TLS configuration updates passed through to the deployed Compose environment.
- A standalone, opt-in server-side partial image updater for GHCR, with persistent
  digest selection, service/package compatibility checks, health checks and rollback.
- Existing frontend/backend, isolated demo data, Registry and payment simulator,
  signed release/update metadata and ordinary DEB installation remain available.

The normal installer is unchanged by the separate GHCR partial-update path. The
standalone client-tools archive includes the new helper; its copy embedded in
the previously completed DEB predates this helper-only addition. Use the
separate signed archive for partial updates.

## Server-side partial update

Extract the verified client-tools archive on the existing deployment server.
For private Packages, run `sudo docker login ghcr.io -u YOUR_GITHUB_USERNAME`
and enter an authorized classic token with `read:packages` at the password prompt.

```bash
sudo bash install-temporary-image.sh install nginx \
  GHCR_IMAGE_AT_VERIFIED_SHA256_DIGEST
sudo bash install-temporary-image.sh status nginx
# Only if a rollback is wanted:
sudo bash install-temporary-image.sh rollback nginx
```

Other selectable services are `profilemanagement`, `registry`,
`payment-simulator`, `mongodb`, `redis` and `minio`. Update one service at a time
with its own compatible digest. `myscoutee-nginx-base` is a build dependency,
not a running service. The helper atomically persists the selected image key, preserves unrelated
configuration and volumes, performs
no demo reset and uses the running deployment's Compose overlays. It does not
perform database migrations. Normal service startup and host reboot retain the patched image, even at
version `1.0.0`. Explicit rollback restores its previous image and setting.
A later DEB installation is separate and can replace the image selection. See the client-tools README for the
full procedure, interrupted-operation limits and credential handling.

An unchanged `1.0.0` tag does not prevent this update: the helper selects an exact
content digest. An already open browser can retain an earlier service-worker
bundle; reload after the update and check the frontend build ID.
