# MyScoutee 1.0.0

Stable Debian release for amd64, following the QA previews.

## Included

- MyScoutee frontend and backend, nginx, MongoDB, Redis and MinIO deployment.
- Isolated Explore/demo data, bundled demo Registry and payment simulator.
- Operator update and rollback UI, client tools, checksums and Ed25519-signed package/update metadata.
- Asset pricing, borrowing, payment summary and lifecycle changes covered by the completed pair-QA campaign.
- Shared action-menu sizing keeps update buttons in one row with truncated labels on desktop and mobile.
- New Explore profile image uploads and profile submission remain in demo storage when Firebase login is configured, without starting a login before onboarding.
- The profile birthday calendar excludes dates younger than 18 years. Typed dates beyond that limit clamp to the latest allowed birthday on blur; the horoscope also updates on blur, without changing the value during typing.

## Versioning and upgrade

The stable version is `1.0.0`, with Git tag `v1.0.0`. No `-rel` suffix is used:
a suffix would make this a prerelease under Semantic Versioning. Operator
comparison and the Debian package ordering both place `1.0.0` above
`1.0.0-qa.3` (`1.0.0~qa.3` in Debian).

The signed update metadata qualifies the direct upgrade from QA3. Earlier QA
versions are not newly claimed as directly qualified upgrade sources.

## Limits

- amd64 only; qualification used the local VMware HTTPS deployment.
- No new public-domain TLS, full protocol, interruption/restore or load campaign is claimed.
- Smoke uses a newly created Explore/demo profile, not a newly registered Firebase account.
- Abandoned anonymous demo image uploads are not evidence of completed registration. Automatic cleanup of those uploads is not added by this release.
