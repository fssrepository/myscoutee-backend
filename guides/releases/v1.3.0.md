# MyScoutee 1.3.0

Release date: 2026-09-28. Git tag: `v1.3.0` on the frontend, backend,
Registry, payment simulator, Java client, admin client and MCP repositories.
Historical releases and tags retain their original contents.

## Included changes

- Personal MCP authorization-code/S256 login, profile-owned clients, revocation,
  refresh replay rejection, per-request identity and API-gated tool discovery.
- MCP in development and production Compose, nginx transport and the Debian
  package; seven bundled managed images instead of six.
- Production configuration parity, preserved deployment settings and versioned
  system seed migration, including common help and missing demo profile details.
- Complete profile filter choices, grouped multi-select controls, consistent
  profile colours and corrected Hungarian labels.
- Profile editor retention below nested image editing, responsive loading
  indicators, retained Firebase login popup through route activation and account
  consent restricted to internal pages.
- Entry Setup uses Login / Bejelentkezés; a successful action continues login.
  Close only cancels. Settings Setup keeps Update. The location acquisition ring
  and full ten-second budget start after permission is granted.
- Offline notification clicks leave the avatar and underlying menu unchanged.
- Deployment qualification recognizes digest-pinned Mongo mirrors using their
  existing upstream label, then checks actual server version and FCV.

## Deployment outputs

The GitHub Pages deployment uses `build:github`, local data and no Firebase login.
The production nginx image and DEB use the separate HTTP-backed `build:prod`.
Both contain version1.3.0. Docker images are published in GHCR; immutable
references and source identities are in the `container-images.json` release asset.
The existing upstream Mongo8.0.4 and Redis8.6.1-alpine versions are retained.

The main GitHub Release includes Operator client tools, checksums and the signed
release manifest. The final DEB is built locally for the owner to upload; Codex
has not uploaded it. Java client archives are attached to its own release.
The admin client's existing tag workflow publishes its private installer and PDF.
MCP plugin marketplace publication is separate from this server release.

## Upgrade path

Older installed packages require six bundled images. Upgrade those installations
with the existing **signed client installer**, `packaging/client-tools/install.sh`,
and the new seven-image DEB. Do not feed1.3.0 to the old in-app update worker or
reuse the historical1.0.2 partial-data helper. Supply the normal release manifest,
public key and independently trusted fingerprint. The installed package provides
its own migration, image verification and host qualification steps.

Production data, media, deployment identity, TLS and operator configuration are
retained. The source images used by the DEB and published GHCR images have
identical filesystems; publication adds service, version and source labels.
No pre-1.3.0 partial-image compatibility is advertised by this release.
The automatic-update catalog was initially deferred until the owner uploaded the DEB.
That follow-up was missed; discovery consequently rejected the published package
with HTTP 412. On 2026-10-10, the missing `myscoutee-update.json` was added using
the retained release key and the unchanged, verified DEB. Its compatibility range
is exactly 1.3.0–1.3.0: it restores authenticated discovery without advertising an
unqualified forward upgrade. Older hosts still use the signed client installer.
The canonical Java discovery and signature verifier passed against GitHub;
pre-1.3.0 versions and same-version reinstallation were rejected before any job
or download. Existing assets and tags were unchanged. See
[the repair evidence](../qualification/evidence/RELEASE_1.3.0_CATALOG_REPAIR_20261010.json).
Netcup was upgraded on2026-09-28 after the user's explicit instruction, using
the signed final DEB through the existing client installer.
