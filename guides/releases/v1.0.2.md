# MyScoutee 1.0.2

Release date: 2026-09-24. Tag: `v1.0.2` in the frontend, backend,
Registry, payment simulator, Java client and new admin client repositories.
The archived `myscoutee-old` repository has no changes since March 2026 and
is not part of this release.

## Included changes since 1.0.1

- Affiliate revenue, payment currency summaries, persisted reference rates,
  scheduled rate refresh and operator configuration.
- Event cancellation, policy/full refunds, approval and republishing behavior;
  calendar exports and recurring/slot event handling.
- Photo feed, gallery metadata, organizer following and content moderation.
  Feed and Followed use the shared menu badge; Followed counts current published
  events by followed organizers, independently of selected filters. Both actions
  remain visible and clickable with zero counts. Table also uses the shared menu
  model and attention badge, preserving its existing visibility condition. Three
  rendered-component tests verify labels, badge transitions and click events
  against the actual menu models.
- Mingle and integration event/participant operations, plus the updated Java
  client; the new Linux admin client starts at version 1.0.2.
- Mongo-backed English/Hungarian translations and local frontend improvements.
- Demo location updates now persist through the HTTP backend. HTTP profile
  coordinates become visible only after a successful save, so polling cannot
  replace an optimistic first location with an unsaved server value.

## Upgrade data and configuration audit

The release compares configuration and system seeds against 1.0.1, and
supports the existing schema-3/4/5 configurations through the ordered chain.
Each completed migration is recorded with its source checksum. Repeats skip
completed steps; a failed step is not recorded and can resume. A newer,
unsupported source schema or changed recorded migration is rejected.

Schema migrations run before seed synchronization. The latter runs on every
release, including when every migration has already completed:

- Configuration schema 4/5 migration preserves operator settings. Migration
  006 adds the FX URL only when absent; an explicit blank, null or custom URL
  is retained. Production and Explore use their own packaged source defaults.
- New exchange-rate defaults and missing scheduled jobs use insert-only
  upserts. Existing observations and operator job overrides are retained.
- Country partitions and i18n messages/bundles are package-owned catalogs.
  Message rows are loaded before the bundle version is published.
- Production and Explore both have the feed, moderation, Mingle and account
  deletion warning indexes supplied by the backend startup initializers.
- Feed and other new user-content collections are created by their owning
  application paths. Existing users, events, assets and media are not replaced
  with demo seeds. Historical payment EUR projections may be filled by the
  existing backend projection worker after startup.

The API, production nginx routes, simulator and Registry come from the same
release images in development-independent deployment packaging. The private
simulator FX origin is allowed only in the Explore database context;
production uses the configured public HTTPS source.

## Downloads and rollout

Container references are listed in `container-images.json` on the frontend
GitHub Release. Docker archives are not GitHub Release assets.

`myscoutee-partial-update_1.0.2.tar.gz` contains the versioned schema/seed
prerequisites. Extract it on the target and run:

```sh
sudo bash ./apply-partial-release-data.sh "$PWD"
```

Then use the client-tools `install-temporary-image.sh install SERVICE
<immutable-GHCR-reference>` for each selected service. Existing compatible
1.0.0/1.0.1 package installations retain their DEB identity and volumes.
Private GHCR access requires the operator's Docker login.

The owner uploads `myscoutee_1.0.2_amd64.deb` separately; its checksum and
signed release manifest are provided with the small release assets. The
automatic-update catalog is not changed before that upload is available.
Netcup was not modified. Historical session evidence establishes earlier
partial updates there, but does not establish its current live version.
