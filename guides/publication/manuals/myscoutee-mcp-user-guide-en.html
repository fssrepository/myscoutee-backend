1. Start Here

MCP connects an AI assistant to MyScoutee’s existing tools. You describe a task in chat; the assistant calls the operations available to the connected profile. MyScoutee still checks permissions, ownership, group membership and the current state of each record.

For normal ChatGPT or Claude use, choose a remote OAuth connection. Each person signs in to their own MyScoutee account and approves a profile. You do not need the publisher’s account, a shared password or a manually copied API secret.

Your AI clientChatGPT or Claude
→
MyScoutee consentYour profile and saved permissions
→
Existing app servicesAuthorized tools and records

Your first connection

  1. Sign in to the intended MyScoutee installation and select the profile or workspace you want to connect.
  2. Open the profile editor’s Affiliate / API popup and locate AI / MCP connections. Administrators use their existing API settings entry.
  3. Set the main MCP access pack. Its initial value is Blocked. Save the parent settings after confirming the permission selector.
  4. Copy the MCP URL. Add it in ChatGPT or Claude using sections 5–6.
  5. Complete MyScoutee sign-in and approval. Read the profile/group shown on the consent screen.
  6. Review the new entry under OAuth permissions. Its initial client pack is Write; set Read or Full if needed and save.
  7. Ask the assistant to identify the connected profile and list available capabilities before performing your intended task.
Which pack should I choose?Write supports organizing commands. Read adds application queries. Full adds change subscriptions through MCP Events. Read and Full include Write; Read is not a separate read-only member connection.

The browser-only local demonstration can show settings but cannot provide an external OAuth service. Use a deployed backend with a reachable HTTPS endpoint. Your installation operator provides that address.

The identity stays fixed

A connection belongs to the issuing profile and, where applicable, its workspace. Switching groups in the MyScoutee interface later does not retarget that connection. To work in another group, authorize a separate connection for that group and give it an identifiable name in your AI client.

Registration identifies the external software. Authorization gives that software access to one person’s profile. Registering a client alone grants no member data. Every other user must sign in and approve their own connection.

3. Access Packs and Effective Permissions

The shield button next to a copied address or credential opens the shared permission popup. Its color follows the selected pack. The popup shows a short explanation under the four-position control.

Amber		Supported organizing commands and their necessary results, including managed-event links and completed encounter exports.Create a draft campaign or organize an event from information you supply.

Read makes more information availableRead and Full let the connected assistant retrieve information the profile may access. This can include conversation content and ratings. Select the pack with that data access in mind. Full does not grant human-decision or administrative write operations.

Main MCP limit and individual clients

The main MCP pack limits all MCP clients for the selected profile. Each client also has its own pack. The effective permission is the lower of the two. A regular API key uses its own saved client pack; the main MCP switch is not a global API switch.

Confirm the selector, then save the parent

Choose a pack and press the permission popup’s tick. This updates the parent draft and button color. Press the parent settings tick to persist all access changes together. Closing the selector with X discards its unconfirmed change; closing the parent without saving does not apply the staged packs.

For an administrator or operator integration, role rules further restrict these packs to the statistics described in section 9.

4. Generate and Manage Clients

Where a client comes from and how it is saved
ClientCreationWhat you seeInitial access
Remote OAuth permissionStart connection in the AI client, sign in, approve the profile.A connected application under OAuth permissions, with its details and revoke action.Write; capped by main MCP.

Generation creates a credential immediately. Access-pack editing is a separate staged settings change. A new key does not change the main MCP switch. The active-client counter shows remaining capacity; the backend allows up to three active keys in each relevant scope. Automatic and manual MCP connections share the MCP scope.

Manual MCP client, when explicitly required

  1. Open MCP Advanced from AI / MCP connections.
  2. Press Generate key. The new row appears directly; no extra name/callback form is required.
  3. Copy the client ID and secret into the external client’s OAuth credential fields. The complete secret is shown only at creation.
  4. Check the callback requirements with your installation operator. The client must return to an exact callback already allowed by this deployment.
  5. Set the row’s pack and the main MCP pack, then save the parent settings. Complete sign-in and profile approval in the external client.

API keys for local software

Copy a newly generated API token into the software’s credential configuration. The external API client supplies a stable UUID of its own. The first successful connection binds the key to that client ID; a different UUID cannot reuse it. Retain the same UUID when restarting or upgrading that client.

The prefix shown after the one-time reveal is an identifier, not a usable token. If you lose a secret, revoke the old credential and generate a replacement. Do not paste tokens, OAuth codes or secrets into a chat prompt.

MCP connections and manually generated MCP credentials use a 90-day lifetime in this revision. Always check the expiry shown in the row. Revocation and expiry stop access even if a copy of the credential remains in the AI client.

5. Connect ChatGPT

Prepare MyScoutee first: choose the issuing profile, enable the main MCP pack, save, and copy its complete HTTPS MCP URL.

Add the custom connection

  1. Open ChatGPT Plugins. Use + → Add custom MCP server.
  2. Enter a recognizable name and the copied MCP URL. Select the OAuth option offered for the server.
  3. Review the connection notice, acknowledge it if you agree, then choose Create as a plugin.
  4. Complete the MyScoutee sign-in and approval when prompted. Review the displayed profile/group.
  5. Install the plugin. In a new chat, use @ to select it and ask for available MyScoutee capabilities.

ChatGPT menu sequence: official connection quickstart, checked 7 October 2026. Availability is controlled by the account and workspace.

Finish the MyScoutee permission setup

Open OAuth permissions in MyScoutee and inspect the newly authorized client. For summaries and general queries, set both main and client to at least Read. For MCP Events, set both to Full. Save the settings; then refresh the client’s tool discovery or reconnect if it still shows the old set.

Automatic OAuth registration needs no manually generated secret. If this host version requires a predefined OAuth client instead, use section 4 and have the installation operator configure its exact callback. Do not substitute an API token in an OAuth field.

If the option is missing

Check the current official setup page and your workspace’s plugin controls. A MyScoutee Full pack cannot unlock an unavailable feature in ChatGPT. This guide does not promise a public MyScoutee marketplace listing or a particular subscription plan.

Connection success is only the first checkVerify the issuing profile and a permitted read or organizing operation. A plugin showing anonymous help does not prove that personal authentication succeeded.

6. Connect Claude

Use the same deployed HTTPS MCP URL and profile preparation as for ChatGPT. MyScoutee advertises automatic OAuth client registration; its current server does not advertise client-ID metadata documents.

Add a remote custom connector

  1. Open Customize → Connectors → + Add → Add custom connector.
  2. Enter a name and the copied MCP URL, then continue through the detected authentication settings.
  3. Where OAuth identity choices appear, select Register automatically for this MyScoutee implementation.
  4. Choose sign-in, complete MyScoutee authentication and approve the correct profile.
  5. Enable the connector from the chat’s + connector controls before using it.

Claude’s remote connectors are cloud connections, including when used from desktop: localhost or a private network address is insufficient. Current documentation includes custom connectors on Free, Pro, Max, Team and Enterprise; Free allows one. Managed organizations may require an owner to add the connector, followed by each member’s own authorization.

Claude: custom connectors using remote MCP, checked 7 October 2026.

After approval

Check the OAuth permission row in MyScoutee. It starts with Write access. Raise it to Read for application summaries and save; the main MCP pack must allow that level too. Confirm the issuing profile before asking Claude to change records.

If your environment requires predefined OAuth credentials, select its own-client option and use a generated MCP client from section 4. Callback configuration belongs to the installation operator. Repeatedly generating credentials will not repair an unregistered callback.

Tools, scheduling and Events are separate capabilitiesA working Claude connector establishes tool access. It does not establish support for MyScoutee’s MCP 2.0 Events extension. Use scheduled queries where appropriate; enable an Events workflow only when the host actually discovers and supports it.

7. Check Your First Connection

Start with a small, observable request. The assistant should identify its current scope and available tools rather than guess which profile it represents.

First prompt

“Check my MyScoutee connection. Tell me the connected profile and workspace, the effective access pack, and the operations available to this connection. Do not change anything.”

The backend’s capability response identifies the issuing profile/group and available operation IDs. The MCP adapter uses that response for discovery and checks it again on personal calls. A tool list may shrink when access is reduced, membership changes or a role is removed.

Use the live help

Ask “Read the current MyScoutee help for campaigns in Hungarian” or “Find the help topic for community cases.” The help tools list, search and read the active revision. They do not use a separate embedded copy of the manual. Operator changes to the active help therefore remain available to the assistant.

Read the result precisely

A successful discovery does not mean every record is accessible. Normal ownership, visibility, version and lifecycle rules still apply to each operation. An empty list can be a valid result. A permission or connection error is not evidence that no records exist.

The adapter supports 40 API operations. Your connection receives the subset allowed by its profile, group, role and pack. The following table groups them by practical use; it is not a grant to access every record.

Decisions that remain with the person

Personal interest scores, granular ratings, ballot choices, personal participation decisions, endorsements and offer decisions stay in the application. These actions depend on the person seeing the relevant context and making their own decision. Full access does not unlock them for an assistant.

For ratings queries, omitting a campaign filter returns the aggregate view. Aggregation uses averages, so values such as 8.5 are possible. Reading an aggregate does not authorize writing a rating.

Working with existing records

Updates require the current record version. If another person changes the record, read it again and review the proposed change before retrying. Creating a batch uses stable caller-owned IDs so a retry can return the existing result without duplicating the resource. Do not invent new IDs just because the first response was lost.

Multipart image/file uploads and developer webhook configuration are not exposed as MCP tools. Readable records may include attachment metadata, but this does not imply a general document-upload tool. Use the application for the supported attachment workflow.

9. Administrator and Operator Access

Installation administrator and operator profiles have a separate read-only integration scope. The server checks the role currently held by the base profile; a role label supplied in chat cannot grant it. Community-group administration remains subject to the ordinary community permissions in section 8.

Current roleRead / Full queryFull Event
Installation administratoradminOverview: current administrator statistics and attention counts.admin.attention: node-member-joined, report-submitted or feedback-submitted attention signal.
OperatoroperatorMeasurements and operatorRevenueReports: paged persisted activity and revenue reports.operator.attention: node-member-joined or release-available attention signal.

Read is the minimum role-query pack. Full adds the matching role Event; it does not add member queries or write commands to the role connection. Write alone does not expose these role statistics.

Report pages default to 25 records and are bounded to 1–100. Ask for a period and a page size rather than an unbounded export. These reads use already persisted reports: they do not trigger synchronization, retry a payment, perform a payout or change configuration.

Operator prompt

“Read the first page of available revenue reports, up to 25 records. Summarize the covered periods and totals, and identify missing information. Do not synchronize or change anything.”

Administrator prompt

“Read the current administrator overview and summarize which attention counts need review. Leave moderation and configuration decisions to me.”

Role Events carry a bounded signal rather than private member content. The assistant can then query the authorized statistics. It cannot use the signal to bypass role checks or perform moderation. Delivery stops when the current role or required permission is lost.

Existing administrator desktop APIThe pre-existing admin-key overview endpoint remains supported and can be blocked. Its compatibility behavior is separate from the new Read/Full role-query contract. See the administrator client’s documentation for that client.

10. Follow Changes with MCP Events

MCP Events lets the host subscribe to a supported change. The server sends a compact notification when it occurs. This differs from asking a scheduled task to reread a list every morning, and from a MyScoutee event that people attend.

For MyScoutee, Events requires remote OAuth, Full on both main MCP and the client, a supported host, and access to the selected resource. Anonymous help and static API-key stdio do not advertise Events.

Use Events in ChatGPT

Current OpenAI documentation supports Events in a Work chat on the web, or a desktop Work chat with Cloud selected. Refresh the plugin’s discovery after a capability change. Describe what to watch and what the assistant should do when a matching update arrives. The host supplies the callback and manages subscription refresh; you do not paste a webhook secret into the conversation. Official MCP Events guide.

Monitoring prompt

“Subscribe to changes for my managed event [external ID]. When it changes, summarize the reported change in this chat. Do not modify the event or send invitations. Stop monitoring when I ask.”

Lifetime, stopping and missed changes

MyScoutee subscriptions last at most one day per grant and need host refresh to continue. Ask the host to stop monitoring to unsubscribe. To stop Events from MyScoutee while retaining queries, save Read on the main link or relevant client. To stop the connection entirely, use Blocked or revoke its authorization.

Delivery uses a bounded queue and retries; duplicates or delays are possible. There is no replay history. After expiry, an interruption or a reported gap, request the current resource state instead of assuming every change was delivered. The host’s acknowledgement of a notification is not proof that the requested follow-up completed.

Changing access, revoking the connection, losing membership, ownership or a required role prevents further eligible delivery. Existing chats and information already retrieved by the host are not erased by revocation.

Ordinary connector support is not evidence of MCP Events support in Claude. Its scheduled-query workflow is documented separately below. Development Events/OAuth checks passed on 15 October 2026; acceptance by the actual external host remains separately qualified.

11. Scheduled Tasks: Where and How

Three different features
FeatureWhat starts itWhere to manage it
AI scheduled taskA time or recurrence you choose; it calls available connector tools.The AI provider’s Scheduled area, subject to account/workspace support.
MCP Events subscriptionA supported change to an authorized MyScoutee resource.The subscribing host/chat; MyScoutee access packs and revocation also control delivery.
MyScoutee community recurring taskThe application’s saved recurring task definition and lifecycle.The community task interface, or permitted task tools. It is an application record, not a ChatGPT/Claude automation.

ChatGPT: Scheduled

When enabled for your workspace, ask ChatGPT to schedule a prompt and specify its cadence and destination. Open Scheduled on the web or desktop to review tasks and recent runs. A task can return to the same chat or run independently. Web tasks use connected tools and uploaded context; tasks requiring local projects need the computer and desktop app running. Plugins can be used by supported Work scheduled tasks. Test the prompt in a normal chat first and inspect the initial runs. ChatGPT scheduled-task documentation.

Claude: Scheduled / Cowork

Current scheduling is available on Pro, Max, Team and Enterprise. Open Scheduled in the sidebar to review runs, edit cadence or instructions, pause, resume or delete a task. In the newer experience, request a schedule in chat and review it before choosing Schedule. Cowork also offers Scheduled → New task. Cloud tasks can run with the app closed; local tasks need the device. Some older Pro/Max tasks created before 6 October 2026 remain local during the rollout. Verify the task’s own execution environment. Claude scheduling documentation.

Choose permission by the work performed

A recurring summary of campaign or case data needs Read, not Full merely because it runs on a schedule. Full is needed for MyScoutee Events. A timed organizing command still needs its normal Write permission and ownership. Host scheduling availability and MyScoutee permissions are independent checks.

Recurring summary prompt

“Every weekday at 09:00 Europe/Bratislava, summarize open cases available to this MyScoutee connection. Include the time checked and record IDs. Report connection errors explicitly. Return here; do not change cases or contact anyone.”

Put the intended profile, scope, timezone and stop condition in the task. Removing an MCP connection may leave an AI schedule present but failing. Pause or delete the schedule in the provider as well when retiring the workflow.

Use these as templates, replacing brackets with real information. They describe supported operations; they do not bypass normal permission checks. Do not include secrets in any prompt.

From a draft to publication

Campaign creation returns a draft. Review it in the application, or request its details with Read access. Publish only the record you intend to publish. An assistant can use the existing supported publication command when explicitly asked; the interface does not add a separate AI approval workflow.

When information is missing

Ask the assistant to identify missing fields rather than fabricate times, participants, availability or scores. A Write connection can organize from supplied information but cannot discover the general application data available only through Read. Raise access deliberately if the task requires it.

When a record changes during the task

A version conflict means the previous view is stale. Read the updated record and reconsider the operation. Do not keep retrying an old destructive action or switch to a broader profile to avoid the conflict.

Check what was actually saved

The permission selector’s tick applies to the draft. The parent tick persists it. Reopen the settings when checking a saved change. Generation and revocation act on credentials separately; closing the parent does not undo a key that was generated or revoked.

Existing data in the AI provider

Blocking or revoking stops future authorized access. It does not delete a conversation, summary, scheduled-task output or file already held by the AI provider. Use that provider’s own controls to manage retained material.

Shared devices and organizations

Check which MyScoutee session is active on the consent screen, particularly on a shared device. Organization-level connector installation does not authorize every member as the installer. Each user must connect their own account; do not distribute one person’s key as a team credential.

15. Local Clients and Technical Reference

This section is for clients that launch an MCP process locally. It is not required for the normal remote ChatGPT/Claude connection. Use the released or installation-provided adapter command in your local MCP client’s configuration.

Local process settingMeaning
MYSCOUTEE_API_BASE_URLHTTPS API root ending in /api, not the full integration prefix.
MYSCOUTEE_API_TOKENThe profile’s ordinary API integration token, stored as a credential.
MYSCOUTEE_CLIENT_IDThat API client’s stable UUID. Keep it unchanged after first binding.

Without a key the local adapter provides help only. Supplying only part of the identity fails startup. A static-key stdio connection can use its authorized API operations but cannot subscribe to MCP Events. Do not put one user’s private key into a shared public HTTP MCP process.

OAuth and transport summary

ItemCurrent implementation
Personal remote path/mcp/private, using deployment-specific HTTPS origin.

RevocationUse the app’s permission/key revoke actions. A separate OAuth revocation protocol endpoint is not advertised.

Subscriptions are bounded to 100 per profile. Delivery uses the existing queue with finite retries, concurrency limits and per-process throttling. These controls protect the server; they do not guarantee instant or lossless notification. Installation operators manage limits and deployment health through the existing operational configuration.

Creating a plugin package or registering a custom connection does not publish a public marketplace listing. OAuth reachability, provider acceptance and final runtime QA must be verified for the actual deployed installation.

MCPThe protocol through which an AI client discovers and uses MyScoutee tools and supported Events.
Host / clientThe application connecting to MyScoutee, such as ChatGPT or Claude.
OAuth permissionYour authorization for a particular external client to use the selected profile.
Client ID / secretAn OAuth client’s identifier and, for predefined clients, its credential. These differ from an ordinary API token.
Effective packThe permission left after the relevant main/client limits and role rules are applied.
Resource IDThe identifier required by an operation. Events for managed assets/events use their integration externalId; role Events use node.
DiscoveryReading the current identity and capabilities. It grants no additional access.
SubscriptionA host request to receive a specified supported change until stopped or expired.
