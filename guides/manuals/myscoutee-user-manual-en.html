Validity and maintenance

This manual describes MyScoutee 1.4.1 and the workflows implemented in its source code. On a newer release, a differently configured deployment, or a custom-branded installation, on-screen labels and available features may differ. In that case, the interface, privacy notice, and terms of use for that deployment take precedence.

Branding differences The product name, colours, and certain labels can be configured for each deployment. In this document, “MyScoutee” is the collective name for the product and its associated legal, support, and moderation processes.

1. Using this manual

1.1 Purpose and scope

MyScoutee is a group- and event-centred social application. Users can create a profile, assign an affinity priority from 1 to 10 to other profiles or pair suggestions, find and organise activities, and manage event-related chats and resources.

This manual describes the standard user workspace. System administration and operations are covered in separate manuals. Host features are included here because a standard user can create and manage an event.

1.2 Notation and interface conventions

Notation Meaning
“Label” A button, menu item, or field shown in the interface. Exact wording may differ because of translation or branding.
Green tick Save, apply, or approve. When shown in red, it generally indicates missing required information.
Three-dot/card menu Actions for the relevant profile, event, message, or asset.
Red counter An unread item or pending action; it does not necessarily indicate an error.
Dialog Most features open above the /game workspace rather than on a separate browser route.
Actions requiring confirmation Always read the confirmation dialog before deleting or rejecting an item, leaving an event, publishing or unpublishing an event, or deleting an account. Some list removals move an item to Trash, whereas account deletion is scheduled and ultimately removes data permanently.

1.3 Boundary between demo and real data

Operating mode Where is the data? What does it mean for the user?
Local/offline prototype, including the GitHub Pages prototype The browser's local seed adapter and local storage. Demo data. It is not a real account or community, and it is not reliable production storage.
Backend-connected Explore demo in development, E2E, or production environments Angular interface → Java HTTP API → isolated MongoDB demo_db. Registry operations use a separately seeded Go demo registry, SQLite database, signing identity, and volume. Server-side, but still isolated demo data. It neither shares nor controls live operator registry state.
Live production mode The authentication, account, and application backends of the relevant deployment. Real user data. The deployment's privacy notice and retention rules apply.
Do not treat a demo as a live service Joining, rating, chatting, booking, or deleting in a demo does not prove that the action involved a real person, event, or payment. Do not enter real payment information or personal information that you would not want stored in a demonstration environment.

Payment integration is enabled in backend-connected production and development builds and disabled in the browser-only demo. Explore uses its isolated simulator. A live deployment still needs configured provider credentials; a cart or payment summary alone does not prove a successful charge.

2. Quick start

1. Sign in

Open the landing page, accept the active privacy version, and select an available Google, email, or demo sign-in method.

2. Profile

Enter the required basic details, upload at least three images, select a language, and save the profile.

3. Explore

On /game, select a recommendation mode, apply filters if needed, and assign a value from 1 to 10 to the displayed cards.

4. Event

In the avatar menu, open “Activities” → “Events”, start Explore, then view the event or request to join.

First successful session

  1. Open the URL of the relevant deployment. The landing route is /, and the sign-in route is /entry.
  2. Read the privacy document, select optional sections according to your own choices, and approve the active version.
  3. Select a sign-in method. For live use, use authentication enabled by the deployment. For demonstrations, select only a profile explicitly identified as a demo.
  4. If required by the deployment, allow location access and wait for the regional eligibility check.
  5. Complete and save the required profile setup. Closing it signs you out, so do not abandon it without saving.
  6. Open a profile from a recommendation card, then select an affinity value from 1 to 10.
  7. Use the avatar menu to review notifications and counters for pending actions.
You are ready Once the profile is saved and the /game workspace is displayed, recommendations, profiles, events, and—while online—chat are available.

3. Sign-in, registration, and first launch

3.1 Sign-in methods

Options shown on the landing page depend on the deployment. A Firebase-based deployment may provide Google and email sign-in. The Facebook option is disabled and marked “Coming soon” in the current interface. A build with Firebase sign-in disabled may open a demonstration profile selector instead.

Sign in with a Google account

  1. On the sign-in page, select Continue and then the Google provider.
  2. Select the account in the Google window and review the requested permissions.
  3. Return to MyScoutee. For a new account, the application opens profile setup.
  4. If the provider requests email verification or another check, complete it as instructed by the provider.

Sign in with a demo profile

  1. Use this only on a deployment whose interface clearly identifies a demo or profile selector.
  2. Read and accept the active privacy notice.
  3. Select a demonstration profile.
  4. Treat every item in the resulting workspace as non-live, isolated demonstration data.

3.2 Email sign-in and account creation

Use an existing email account

  1. Select “Continue with email”.
  2. On the “Email sign-in” panel, select the sign-in tab.
  3. Enter a valid email address and a password of at least 6 characters.
  4. You may use the eye icon to check the password, but shield the screen in public.
  5. Select “Sign in” and wait for the profile to load.

Create a new email account

  1. On the email panel, select the account creation tab.
  2. Enter a valid email address.
  3. Create a password of at least 8 characters containing a letter and a number. A symbol is recommended but optional.
  4. Enter the same password again; the two fields must match exactly.
  5. Select “Create account”.
  6. If a verification email arrives, open it, complete verification, and return to the application.
  7. Complete the required profile setup.
Password security Use a unique password, do not share it, and do not enter it into a demo or a deployment of unknown origin. The current sign-in panel does not provide a separate “forgot password” workflow; use the support channel for the relevant deployment.

3.3 Privacy consent

The active privacy document must load before you sign in or open a demo profile. In addition to the mandatory approval, the document may contain optional sections that you can select separately.

Set privacy choices

  1. Read the displayed privacy version and all its sections.
  2. For optional sections, select only those to which you genuinely consent.
  3. Select the approve/continue action.
  4. After signing in, review and save the current choices under “Settings” → “Privacy”.

The sign-in choice creates local state and an audit entry. The authenticated account's settings view also synchronises the choice with the backend. A new privacy version may require consent again. Public documents are available without signing in at /privacy-policy and /terms.

3.4 Conditional location permission

Location is not mandatory on every deployment. If the active sign-in policy requires location data, the application displays a separate “Enable location” dialog, requests browser GPS/location permission, and asks the backend to check regional eligibility.

Check location-based eligibility

  1. Select “Enable location”.
  2. In the browser permission request, allow access only if you trust the deployment.
  3. Wait for the region check result.
  4. If permission is denied, location is unavailable, or the region is ineligible, sign-in cannot continue. Change the browser's site permission or contact deployment support.

3.5 Required profile setup

Setup is mandatory for a new Firebase account, a profile in onboarding state, or an outdated profile form version. The visible required information is name, date of birth, city, height, body type, at least one language, and at least three profile images.

Complete profile setup

  1. In “Basics”, enter your name, date of birth, city, height, and body type, then select at least one spoken language.
  2. Enter any additional information you wish to share: introduction, gender, work experience, or education.
  3. In “Photos”, upload at least 3 and no more than 8 images.
  4. Under “Lifestyle”, optionally set alcohol use, smoking, exercise, pets, family plans, children, love and communication styles, sexual orientation, religion, values, and interests.
  5. Review required fields; an incomplete field may be highlighted in red.
  6. Select the green save tick and wait for a successful save.
Do not close an incomplete setup Closing the mandatory profile setup signs you out and redirects you to /entry. Uploaded images must not show identity documents, financial data, an exact home address, or another person without their consent.

4. Navigation, installation, and availability

After a successful sign-in, the main workspace is /game. /home redirects to it. If you open a protected page without authentication, the application redirects to /entry?redirect=…; onboarding also opens when the profile is incomplete. An administrator or operator role is directed to its own workspace rather than the standard user view.

4.1 The avatar menu

Group Features Purpose
Impressions Impressions, Feedback Host and attendee impressions and post-event feedback actions.
Activities Ratings, Chats, Invitations, Events, My events Previous activity, pending event actions, and hosted events.
My assets Transport, Accommodation, Supplies, Tickets, Contacts Owned or managed resources, admission codes, and quick contact methods.

Header actions include “Notifications”, the explanatory help overlay toggle, sharing the currently branded product, and “Settings”. Badge counts indicate pending or new items.

4.2 Settings

  • Help: active only when a help version has been released for the deployment.
  • Send feedback: submit a product observation or defect description.
  • Global identity: manage a separate, voluntary, privacy-preserving identity link.
  • Report bugs: open the external GitHub issue page.
  • Privacy and Terms: view the current legal documents.
  • Delete account and Sign out: account actions that require confirmation.

4.3 Install on the home screen

Install the PWA

  1. On a deployment released with service-worker support, wait for the “Add to home screen” offer.
  2. Select install/add. If the browser does not show the offer, use its “Install app” or “Add to home screen” menu.
  3. After acceptance, the interface may request notification registration for the active user. Decide separately whether to grant the browser permission.
  4. Launch the application from the new icon and verify that the correct deployment opened.
Deployment-dependent feature The PWA offer is available only in a build where the service worker is enabled and the browser satisfies the installability requirements.

5. Recommendations, filters, and ratings

5.1 Select a recommendation mode

Mode Content Additional field
Preferences Individual profile cards. No required pair of people.
Friends in Common Individual profiles suggested through shared network connections; this is not a pair mode. No paired-person search.
Inside Network A pair suggestion showing two people inside the network. Person and friend search fields may be shown.
Outside Network A pair suggestion showing two people outside the network. No text-based person or friend search is shown.

Rate a profile or pair

  1. Open the mode selector in the /game header.
  2. Select the required individual or pair mode.
  3. In “Inside Network”, use person and friend search if needed. The “Outside Network” pair mode does not display these text searches.
  4. Open the card and review the visible profile. Only fields that the person has shared for your context are displayed.
  5. Select a value from 1 to 10 on the “Affinity” bar.
  6. After saving, the interface moves to the next card. A previous value can be changed in “Ratings” when the card remains editable.
Profile status A profile generally needs “Public” status to appear and be rateable in normal recommendations. “Friends only”, “Host only”, and “Inactive” restrict or pause visibility.

5.2 Recommendation filters

Apply a filter

  1. Select the filter icon in the recommendation view.
  2. Set values under “Basics”: age and height ranges, body type, languages, genders, zodiac sign, and highlighted trait.
  3. Under “Beliefs”, select values and religion.
  4. Under “Lifestyle”, filter by interests, smoking, alcohol use, exercise, and pets.
  5. Under “Relationships”, set family plans, children, love and communication styles, and sexual orientation.
  6. Apply the filter with the green tick. Closing the dialog without applying discards the changes.

5.3 Rating history

Open the list with the history icon or “Activities” → “Ratings” in the avatar menu. Individual mode provides “Given”, “Received”, “Mutual”, and “We met” filters. Pair suggestions provide “Given” and “Received”.

Change a previous value

  1. Open “Ratings” and select the appropriate mode and filter.
  2. Find the card; switch to full-screen view if necessary.
  3. Open your rating and select a new value from 1 to 10.
  4. Verify that the new value appears on the card. A pair-mode “Received” row may be read-only.

6. Profile, impressions, and contacts

6.1 Open your profile and set its status

Edit the profile

  1. Open the avatar menu, then select your profile or the profile header.
  2. In the profile dialog, switch among “Profile”, “Images”, and “Experience”.
  3. Change the required fields. Required form fields may remain red until they are valid.
  4. Set profile visibility in the header status selector.
  5. Select the green tick and wait for saving to finish. A progress indicator or error may also appear beside the avatar.
Profile status Effect
Public The profile can appear in normal recommendation and discovery workflows.
Friends only Visibility is restricted to a friend or network context.
Host only The profile remains available to a host context.
Inactive Normal discovery presence is paused.

“Blocked” and “Deleted” are system states and cannot be selected from the normal status menu. They are managed by moderation and account deletion processes respectively.

6.2 Profile information and field-level visibility

Basic information, introduction, languages, detailed lifestyle and relationship information, values, and interests can be changed in the profile. Detailed fields can have separate visibility: “Public”, “Friends”, “Hosts”, or “Private”.

Change the visibility of a profile field

  1. Open your profile editor and find the field.
  2. Open the visibility control shown beside the field.
  3. Select “Public”, “Friends”, “Hosts”, or “Private”.
  4. Save the profile with the green tick.
  5. When viewing another profile, remember that you likewise see only fields permitted for your context.
Data minimisation Do not enter an exact home address, identity-document number, financial information, a password, or another person's information without consent. “Private” reduces interface visibility, but it is not a substitute for omitting unnecessary data.

6.3 Profile images

Add or replace an image

  1. Open “Images” in the profile editor.
  2. Select an empty image position or the image to replace.
  3. Select an appropriate image file, then wait for upload and preview.
  4. Reorder or remove images with the available card action.
  5. Keep at least 3 images; no more than 8 can be used.
  6. Save the profile.

Use only images for which you have the necessary rights. Do not upload intimate, unlawful, misleading, or safety-threatening content.

6.4 Create and import experience entries

The “Experience” panel supports “Workplace”, “School”, “Online occasion”, and “Additional project”. An entry includes type, city, title, organisation, start and end dates, and description.

Add an experience manually

  1. Open “Experience”, then select create.
  2. Select a type and complete the relevant fields.
  3. Set visibility for the entry.
  4. Save the entry and then the complete profile.
  5. To change or remove it, open the card menu and select edit or delete.

Import experience from a document

  1. Select the upload/import action.
  2. Upload a supported file: .pdf, .doc, .docx, .odt, .rtf, or .txt.
  3. In the preview, review recognised entries, entries ready for import, and possible duplicates.
  4. Confirm only correct items. Afterwards, open them and correct any misidentified fields.
  5. Save the profile.

6.5 View another profile

Profile details can be opened from a recommendation card, event member, contact card, and other supported contexts. Displayed fields depend on the owner's field-level visibility settings, your relationship, and the opening context.

Review a profile before an action

  1. Select the person's image, name, or “View profile”.
  2. Review the visible basic information, details, and experience.
  3. Do not infer that missing information does not exist; it may be private to you.
  4. Close the dialog to return to the original event, contact, or recommendation.

6.6 Impressions

“Impressions” in the avatar menu shows separate Host and Attendee summaries. The interface may display a badge, level, and notable traits. A change indicator means that a new or changed impression has arrived.

View impressions

  1. Open “Impressions” in the avatar menu.
  2. Select the Host or Attendee segment.
  3. Review the badge, aggregate level, and traits.
  4. Close the dialog. The application may mark a viewed real-time change indicator as cleared.

6.7 Post-event feedback

“Impressions” → “Feedback” is tied to an event and actual participation. It is different from a general profile rating and product feedback. The list may distinguish pending, submitted, own event, and removed entries.

Submit event feedback

  1. Open “Impressions” → “Feedback”, then the pending entries.
  2. Select the event.
  3. Answer the host and/or attendee cards that apply to your role, and select relevant traits.
  4. Add a textual host note if available.
  5. Submit the feedback and wait for the success message.
  6. Verify that the item moved to “Feedback submitted”. For your own event, the host summary may show answers and notes.

If you do not wish to give feedback, you can remove the entry and restore it from “Removed”. The application keeps a submitted result and displays its saved state when reopened; it does not intentionally create a duplicate response.

6.8 Contacts

“My assets” → “Contacts” manages quick-contact cards. Supported methods are telephone, SMS, WhatsApp, email, Facebook, Instagram, Telegram, LinkedIn, and website. A backend-connected deployment uses backend data; a local build uses a local repository. The list therefore cannot be assumed to be browser-only in every environment.

Create or change a contact

  1. Open “Contacts” and select add; for an existing item, open edit.
  2. Select the person or enter the card details.
  3. Add one or more contact methods and verify the phone number, address, username, or URL.
  4. Save the card.
  5. Use the A–Z filter to search. From the card, open the profile or contact method.
  6. When deleting, confirm that you intend to remove only this quick-contact card.
An external application may open Selecting a telephone, email, social, or web contact may launch an external application or website. Before sending, always verify the recipient and the external service's data handling.

6.9 Send product feedback

Submit an observation or defect description

  1. Open “Settings” → “Send feedback” in the avatar menu.
  2. Select a category, such as general feedback or bug report.
  3. Enter the required subject.
  4. Describe the experience in at least 8 characters. For a defect, include reproduction steps, expected result, and actual result.
  5. Before submitting, remove passwords, tokens, personal messages, and unnecessary personal information.
  6. Select send and wait for confirmation.

6.10 Global identity

Global identity is a separate, voluntary feature; it is not Google, email, or Firebase sign-in. The interface may show status, linked period, active/inactive period, and verification times. According to the feature's privacy description, the raw identifier remains inside the deployment, opaque commitments are sent externally, and historical inference is limited.

Link and manage global identity

  1. Open “Settings” → “Global identity”.
  2. Read the displayed privacy guarantees and limitations.
  3. If the feature is not linked, select voluntary consent and start linking.
  4. Review status and the active/inactive period.
  5. For a synchronisation error, use “Reload” or “Retry”.
  6. If rotation is required, select “Rotate”. To unlink, select “Unlink” and verify the result.

7. Events as a participant

7.1 Event lists and views

“Activities” → “Events” in the avatar menu opens event activity. Scopes are “All”, “Active events”, “Pending”, “Invitations”, “My events”, “Drafts”, and “Trash”. You can also select “Upcoming”/“Relevant”/“Past” and a “Day”/“Distance”/“Week”/“Month” view.

Find an event in your activity

  1. Open “Events”.
  2. Select a scope such as “Invitations” or “Pending”.
  3. Select the upcoming, relevant, or past time filter.
  4. Set the list to day, distance, week, or month view.
  5. Open the event card or its action menu.

7.2 Discover public events

Use Explore

  1. From the quick actions in “Events”, select “Explore”.
  2. Select sorting: “Upcoming”, “Past events”, “Nearby”, “Most relevant”, or “Top rated”.
  3. Select a day, distance, week, or month view.
  4. Optionally enable “Friends going” and “Available places”, then select a topic.
  5. On the card, check the title, time, location/distance, visibility, topics, capacity, and host impression.
  6. Open the details before joining, joining a waitlist, or starting a booking.
Event setting Meaning
Public Discoverable more widely, although joining may still depend on approval or capacity.
Friends only Discovery and joining are restricted to the friend/network circle.
Invitation only Not shown in normal discovery; a direct invitation or share is required.
Open Event Standard participants can see the participant preview in advance.
Blind Event The participant preview is hidden from standard members. This does not make the event secret; administrators and managers still manage members.

7.3 Joining, approval, and waitlist

Available card actions depend on the event settings and your status. They may include “Request to join”, “Book event”, “Join waitlist”, “Continue booking”, “Ask host”, “Share”, and “Report host”.

Request to join a free, unticketed event

  1. Open the event and review its description, time, location, capacity, and required policies.
  2. Select “Request to join”.
  3. Confirm the request. With automatic approval, you may become an accepted member; otherwise your status becomes “Pending”.
  4. Review the status under “Events” → “Pending” or “Active events”.

Join a waitlist

  1. If the card shows that the event is full, select “Join waitlist”.
  2. Confirm the request and monitor notifications and invitations.
  3. If a place becomes available, you may receive a waitlist invitation. Acceptance can start further cart, policy, or approval steps.
  4. Do not treat a waitlist place as confirmed participation until the status is accepted or confirmed.

7.4 Accept or decline an invitation

Manage an invitation

  1. Open “Activities” → “Invitations” or “Events” → “Invitations”.
  2. Open the card and review the event.
  3. To accept, select “Accept”. If slots, optional sub-events, policies, a ticket, or a price apply, complete the checkout that opens.
  4. If an accepted member rather than an event administrator sent the invitation, acceptance may be sent for administrator approval.
  5. To decline, select “Decline”, read the confirmation, and approve it.
  6. A declined item may appear in Trash and can be restored from there if necessary.

7.5 Status-dependent event card actions

Status or role Common actions
Discovered, not yet a member View, request to join/book/join waitlist, ask host, share, report.
Pending applicant View, continue booking, ask host, share, report.
Accepted participant View; access members, sub-events, and resources as permitted; payment summary; ask host; report; leave event.
Owned/hosted event View or manage and notify participants; additional host actions are described in Chapter 8.

7.6 Leave an event and use Trash

End your participation

  1. Select leave event from the event card menu.
  2. Read the confirmation. If a booking or price applies, review cancellation terms and any refund preview.
  3. Confirm that you want to leave.
  4. Review Trash. The list action may move the participation record there rather than deleting it permanently at once.

Restore an item from Trash

  1. Select “Trash” from the event scopes.
  2. Find the deleted, declined, or left item.
  3. Select “Restore”.
  4. Check which active list it returned to. Restoration does not guarantee automatic membership or a new booking.

7.7 View members and roles

The member list can show accepted and pending members, roles, participation state, and a capacity summary. “Pending only” filters waiting items. A standard member can view profiles and their own participation context. Inviting, approving, removing, promoting to administrator, banning, and reinstating appear only with the required host permissions.

8. Creating and hosting events

8.1 Create a new event draft

Record the basic event

  1. Open “Activities” → “Events”.
  2. From quick actions, select “Create event” or the plus action.
  3. Upload an event image if one is available.
  4. Enter the required name and description.
  5. Enter minimum and maximum capacity. The maximum cannot be lower than the minimum.
  6. Enter the location. Verify the map-search result and add route points if required.
  7. Enter start and end date/time. The end must be after the start.
  8. Select visibility and event-intelligence settings.
  9. Save with the green tick. The first save creates a draft; the event is not yet published.
Save requirements The implementation requires a name, description, both capacity values, and start and end times before saving. The interface also treats location as an event field. For a live event, always provide a verified location or route that participants can use.

8.2 Visibility and event intelligence

Setting Available values Effect
Visibility Public, Friends only, Invitation only Determines who can discover or request the event.
Participant preview Open Event, Blind Event Determines whether standard participants can see one another in advance; this is separate from visibility.
Topics Up to 5 Supports discovery and relevance-based recommendations.
Auto Inviter On / Off When enabled, may help invite people to available places according to the priority plan.
Ticketing On / Off Connects ticket- and QR-based admission to the event.
Approval Automatic / Approval required Determines whether an applicant is accepted immediately or awaits an administrator decision.
A Blind Event is not a secret event It hides only the participant preview from standard members. The separate visibility setting controls discoverability, and administrators and managers can still manage members.

8.3 Sub-events and stages

After enabling sub-events, select “Casual” or “Tournament”. Casual mode supports required or optional sub-events. Tournament mode supports a sequence of dependent stages.

Add a Casual sub-event

  1. Enable sub-events in the event editor and select “Casual”.
  2. Select add, then choose whether the sub-event is required or optional.
  3. Enter the required name and description.
  4. Enter start and end times, or the required duration in the relevant view; keep the value within the main event's time boundaries.
  5. Enter the location. For an optional sub-event, capacity and a separate price can be entered; the price of a required sub-event belongs to the main event summary.
  6. Save the definition, then save the event.

Add a Tournament stage

  1. Enable sub-events and select “Tournament”.
  2. Add a stage and enter its name, description, duration/time, and location.
  3. Set stage capacity and minimum/maximum group size.
  4. Select a scoreboard type: “Score” or “Fifa”.
  5. Set how many participants/groups advance from each group and check the estimated group count.
  6. If required, position the stage before or after another stage and enter an offset in minutes.
  7. Save the stage and event.

Definitions can be displayed in card or timeline view, edited, and deleted. During a Tournament, an authorised host can manage groups, results, advancement, and stage state. Before finalising, always check all groups and advancement rules. Changing stage state requires confirmation.

8.4 Recurrence and slots

With slots disabled, the event is “One-time”. For an enabled series, available frequencies are “Custom”, “Daily”, “Weekly”, “Bi-weekly”, “Monthly”, and “Yearly”. A particular occurrence can have a separate sub-event or stage override.

Set recurring times

  1. Enable slots/recurrence in the scheduling section of the event editor.
  2. Select the frequency.
  3. Add and edit slot templates; review start, end, capacity, and the main event's time limits.
  4. If one occurrence differs, select its date in the occurrence selector and enter the sub-event/stage override.
  5. Page through nearby occurrences to ensure no incorrect time remains.
  6. Save the event.
Slot and occurrence Changing the series template may affect several future occurrences; an occurrence override belongs to one selected date. Before publishing, verify which level you are editing.

8.5 Policies, pricing, and promotions

Add an event policy

  1. Enable the policies section and open the policy editor.
  2. Enter a title and a clear description.
  3. Specify whether explicit approval is required. A required policy must be accepted by a person joining.
  4. Save the policy, then review it in the checkout preview.

Set a price and promotion

  1. Open pricing and select the currency and fee items.
  2. If the price differs by slot or optional sub-event, assign the line item to the relevant element.
  3. Enter the promotion-code rule and validity period if supported by the interface.
  4. In the summary, verify base price, line items, quantity, and total.
  5. Save the event. Online payment is enabled in backend-connected production and development builds and requires the deployment's configured payment provider. The browser-only demo disables payment integration; Explore uses simulated payments.

  4. Change the structure, save it, and publish again if appropriate.

9. Booking, cart, policies, and prices

9.1 When does checkout open?

Checkout may start after “Book event”, joining a paid or ticketed event, accepting an invitation, accepting a waitlist place, or continuing an unfinished cart. Depending on the deployment and event settings, the workflow can include slots, optional sub-events, policies, a promotion code, and a price summary.

Review and confirm an event booking

  1. Start booking from the event card or an invitation's “Accept” action.
  2. In the slot selector, select the required time or, where supported, multiple required slots.
  3. For each selected slot, select any optional sub-events. Required items may be added automatically.
  4. Check “Booked”/“Full”, remaining capacity, and the date.
  5. Read the policies. Select each required-policy checkbox only if you agree.
  6. If you have a promotion code, open the promotion dialog, add the code, and verify that the summary actually changes. An invalid code can be removed.
  7. Review cart line items, quantities, currency, discounts, and total.
  8. Select confirm/accept. The result may be accepted, pending approval, or waitlisted.
Price and capacity can change The slot, optional item, available place, or price may change during checkout. If the application reports “Cart changed”, review the whole cart again rather than relying on the previous amount.

9.2 Checkout and result states

Status Action
Draft The cart was left incomplete; continue or release it from the card.
Waitlist No place is confirmed; wait for a notification or invitation.
Approval pending Await the host's decision; do not treat this as accepted membership.
Approved The request is approved, but further confirmation or payment may still be required.
Confirmed The booking is active; review the event and ticket.
Pay Requires the deployment's enabled and configured payment provider. Explore uses simulated payments; the browser-only demo does not make live payments.
Failed / Cancelled / Rejected Read the reason, correct the cart, retry, or contact the host.

9.3 Continue or release an unfinished cart

Continue the cart

  1. Open “Events” → “Pending” or select the cart badge.
  2. Select “Continue booking”.
  3. Refresh the slot, optional items, and policy acceptances.
  4. Review the current amount and confirm.

Cancel or release the cart

  1. Open the pending checkout.
  2. Select cancel, delete, or release place, depending on the state.
  3. Read whether the action affects only the cart, pending membership, or the reserved place as well.
  4. Confirm, then verify that the item disappeared from Pending or received the appropriate result state.

9.4 Payment summary

After accepted membership or a previous checkout, “Payment summary” on the event card may display a read-only cart, line items, currency, total, and state. It proves neither a receipt nor a successful bank charge unless that deployment also provides a separate confirmation from an active payment provider.

Check the payment environment before entering card details Explore payment screens use a simulator. Never enter real card details there or in the browser-only demo. For a real booking, check the deployment, named provider, currency, amount and secure provider page before paying.

12. Safety, privacy, and account management

12.1 Report a user, host, manager, or message

“Report user” is not a general profile button. It appears only in a verifiable context, such as an event host, event member, resource manager, or chat message. The report pre-fills the user and event/source context so that moderation can locate the case.

Submit a moderation report

  1. Open the menu for the relevant event, member, resource, or message card.
  2. Select “Report user”, “Report host”, “Report manager”, or “Report”.
  3. Verify the pre-filled user and event/resource context.
  4. Select the appropriate reason, such as harassment or another policy violation.
  5. In at least 12 characters, describe factually what happened, when, and at which message or event.
  6. Do not include unnecessary health, financial, identity-document, or password information. Provide relevant evidence only through a supported secure method.
  7. Submit the report and wait for confirmation.
Immediate danger MyScoutee reporting is a moderation process, not an emergency service. In immediate physical danger, first follow the local authority or emergency procedure and use the application only when it is safe.

12.2 Separate product defects from moderation

Problem Correct channel
Harassment, abuse, a policy-violating user, or message Contextual “Report user” / “Report”.
Product idea, usability feedback, or general application defect “Settings” → “Send feedback”.
Reproducible open-source defect “Settings” → “Report bugs”, which opens the MyScoutee GitHub issue page.
Deployment, access, or data-handling question The deployment's help, operator, or privacy contact.

GitHub is an external service. Do not copy a personal profile, private chat, token, identifier from a log, or other sensitive information into a public issue.

12.3 Manage privacy choices

Review current privacy consent

  1. Open “Settings” → “Privacy” in the avatar menu.
  2. Review the document version and read the current sections.
  3. Change optional selections according to your own choices.
  4. Select “Approve privacy” or the save action.
  5. Wait for “Privacy choices saved”. If an error occurs, do not assume that the change synchronised.

If no valid consent exists for the active privacy version, the document cannot be freely closed until the mandatory decision is made. The terms of use are available separately under “Settings” → “Terms”.

12.4 Location, camera, microphone, and notification permissions

  • Grant location permission only for the sign-in region check or a genuine location-based feature.
  • Grant camera permission for the ticket scanner. Revoke it afterwards in the browser's site settings if appropriate.
  • Grant microphone permission only while recording a voice clip.
  • Enable browser notifications only on a personal, locked device when lock-screen content presents no privacy risk.
  • On a shared or public computer, always sign out and do not save the password in a shared browser profile.

12.5 User state for a blocked account

When blocked by moderation, a user can view their blocked profile, but rating, matching, profile editing, assets, events, and invitations are paused. Chats may remain open, particularly to access the Application support channel.

What to do while blocked

  1. Read the blocking or restriction notice shown in the interface.
  2. Open the “Application support” chat if available.
  3. Refer factually to the account and displayed status. Do not create a new account to evade the restriction.
  4. Wait for an authorised moderation/administrative decision. The block cannot be removed through the normal profile-status selector.

12.6 Sign out

Sign out safely

  1. Open “Settings” → “Sign out” in the avatar menu.
  2. Verify the account name in the confirmation, then select “Sign out”.
  3. Wait for the server-side result. After an error, the application may retain the local session.
  4. On success, the application clears the active profile from the interface, ends the authentication session, and redirects to /entry.

12.7 Delete an account

Schedule deletion

  1. Save any of your data that you lawfully need and resolve pending events, bookings, or loans.
  2. Open “Settings” → “Delete account” in the avatar menu.
  3. Read the warning: the account can be reactivated within 30 days and is permanently deleted afterwards.
  4. Verify the account name and select “Delete”.
  5. Wait for a successful backend response. On success, the account enters deleted/scheduled state, you are signed out, and the application redirects to /entry.
Permanent after 30 days After the 30-day reactivation period, the backend permanently removes the account in accordance with applicable retention and legal rules. It cannot then be restored through the standard interface.

12.8 Reactivate a deleted account

Reactivate during the 30-day period

  1. Within 30 days of deletion, sign in with the same authentication account.
  2. In the non-dismissible “Reactivate account?” dialog, select “Reactivate”.
  3. Wait for the profile to save. The application restores the previous eligible profile status—such as Public, Friends only, Host only, Inactive, or Blocked—and may use Public for an unknown value.
  4. Review profile, event, and asset states. Reactivation may not restore every separately deleted or expired related item.

Selecting “Cancel” in the dialog signs you out and redirects you to sign-in. The dialog cannot be closed by selecting its backdrop or pressing Escape.

13. Offline and limited operation

13.1 Without a network connection

In backend-connected standard user mode, the application restricts server operations without a network. The member-facing notice says that tickets already available may remain accessible offline; other actions must wait for a connection. Chat is expressly online and may be disabled in the avatar menu.

Feature Expected offline state
Tickets An already available ticket list/QR code may open. Load and verify it online before departure.
Chat Unavailable; the menu item is disabled or sending cannot be confirmed.
Profile, rating, event, invitation, asset, booking Waits for connection, may be disabled, or cannot be saved reliably.
Local/offline demo build May behave differently because of the local seed adapter; resulting data is still not live production data.

Prepare for a weak network

  1. While online before departure, open the ticket, event address, time, and location.
  2. Verify that the PWA is installed and the required page has loaded once. This still does not guarantee full offline operation.
  3. For a pending message or save, wait for the network to return and verify the state reloaded from the server.
  4. Do not blindly repeat a booking, borrowing request, or message because the previous request may have arrived in the meantime.
An offline screen is not current proof The cached state of a ticket, event, or asset may be outdated. Refresh the list when a network is available and obtain host verification for critical admission.

Cached sign-in and installed PWA updates

After an online sign-in and warm cache, an installed PWA can restore the cached Firebase session and profile while offline. It still cannot confirm server-side writes without connectivity. Reconnect and let the application refresh the session and data before relying on a changed membership, payment or notification state.

When an application update is ready, follow the update prompt. An update may finish downloading after the first check; leave connectivity available until activation completes. Android Back closes the current guide or popup before leaving its enclosing screen. Backgrounding and reopening the app preserves the ordinary session subject to browser storage, sign-out and server access rules.

13.2 Browser and device limitations

  • The QR scanner requires a camera, a secure website, and browser QR/BarcodeDetector support. Without support, it cannot scan.
  • A voice clip requires a microphone and MediaRecorder support.
  • PWA installation requires an enabled service worker and browser-side installability.
  • External telephone, email, and social actions require the appropriate external application.
  • Location-based sign-in requires browser geolocation, user permission, and a backend region check.

14. Troubleshooting

14.1 General diagnostic sequence

  1. Record which deployment, route, and branded product name you see.
  2. Check the network and confirm that you are not treating a demo environment as a live one.
  3. Read the interface error and wait for any in-progress loading or saving.
  4. Refresh the page once; do not immediately repeat a state-changing action.
  5. Check browser site permissions and the device's exact date/time setting.
  6. If the problem remains, collect reproduction steps, time, role, and non-sensitive screen information, then use the appropriate support channel.

15. Glossary

Term Definition
Active event Event activity for which the user has current membership, an action, or a host relationship.
Sub-event A required or optional part of the main event with its own time, location, capacity, and possibly price.
Affinity A user-assigned priority/affinity value from 1 to 10 for a profile or pair suggestion.
Application support A chat context that may remain available to a restricted or blocked account as a support channel.
Auto Inviter An event setting that may help invite people to available places according to the priority plan.
Backend-connected Explore demo A mode using server-side but isolated demo data; it is not live operator registry or community state.
Blind Event An event whose standard participant preview is hidden; it does not automatically make the event secret.
Checkout The slot, sub-event, policy, promotion, and price review before joining or accepting an invitation.
Friends only Profile, event, or asset visibility restricted to a friend/network context.
Invitation only Event or asset visibility that excludes normal discovery and requires a direct invitation/share.
Host only A profile status or field visibility that makes information available to a host context.
Demo profile A non-live user account or social identity created for demonstration.
Event administrator An accepted member with permission to manage members, invitations, and event actions.
Event feedback A structured response about hosts/participants and the event experience after actual participation; it is not a general profile rating.
Global identity A voluntary, separate privacy link using opaque commitments; it is not the sign-in account.
Local seed adapter The demonstration data source for a local/offline build; it runs in the browser and does not provide production retention.
Inside Network A pair recommendation mode in which person and friend search fields are shown.
Approval pending A join or booking status still requiring a host decision; it is not accepted membership.
Required policy A rule that a person joining or borrowing must explicitly accept before continuing.
Borrowing request A request for an asset for a defined period and quantity that may require owner approval.
Trash A restorable view of declined, left, or list-deleted event activity; it is not permanent account deletion.
Open Event An event where standard participants can see the participant preview in advance.
Public A status allowing wider recommendation or discovery visibility; further membership/approval restrictions may still apply.
Outside Network A pair recommendation mode outside the network; it does not display text-based person/friend search.
Draft A saved but unpublished event, or an unfinished checkout/cart.
Policy An event or borrowing rule that can be required or optional.
PWA A progressive web application that can be installed on the home screen in a supported build and browser.
QR ticket A code linked to an event and person, displayed by the ticket interface and resolved to participant data by the scanner.
Participation The user's membership link to an event, slot, sub-event, group, or resource.
Service worker A browser component that can support PWA installation and limited caching; it does not guarantee full offline operation.
Slot A selectable time/occurrence in an event series that may have its own capacity, sub-event, and price.
Poll A chat attachment with one question and 2–6 options; a user's vote can be changed.
Ticketing An event setting that enables the ticket- and QR-based admission interface.
Tournament A multi-stage sub-event mode with group capacity, scoreboards, and advancement rules.
Waitlist A queue for a full event; joining it does not guarantee participation.
